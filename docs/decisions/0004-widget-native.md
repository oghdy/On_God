# ADR-0004 — 위젯: 네이티브 직접 작성 (Expo Config Plugin)

- 상태: 채택(Accepted)
- 일자: 2026-06-28
- 관련: Phase 3 전체, SRS 8장 미결사항

## 배경

SRS 8장이 위젯 구현을 "네이티브 직접 작성 vs 서드파티 라이브러리"로 미결로 남겼다.

## 결정

**Expo Config Plugin**으로 네이티브 위젯(iOS WidgetKit / Android Glance)을 직접 작성한다.

## 근거

| 기준 | 네이티브 직접(채택) | 서드파티 |
|------|--------------------|----------|
| 디자인 자유도 | 앨범아트 몰입형 완전 제어 | 제약 많음 |
| 장기 유지보수 | OS 업데이트 직접 대응 | 라이브러리 방치 리스크 |
| 학습 비용 | 높음(초기) | 낮음 |
| OnGod 적합성 | ★ 앨범아트가 핵심 가치 | △ |

- OnGod 핵심 가치(SRS 1.2)가 "시각적 완성도 — 앨범 아트 중심". 위젯이 그 가치가 가장 직접 드러나는 표면.
- RN 생태계의 위젯 서드파티는 유지보수 불안정 사례가 많아 장기 운영 앱엔 부채.
- Phase 3 범위를 소형 위젯 하나로 좁혀 초기 학습 비용을 감당 가능 범위로 통제.

## 영향

- `expo prebuild` 필요, bare 워크플로 전환 검토.
- iOS: App Group 공유 컨테이너 / Android: SharedPreferences·DataStore로 앱↔위젯 데이터 공유.
- 위젯은 로컬 캐시를 읽고, 갱신은 백그라운드 task가 담당(위젯 직접 네트워크 최소화).
